# Using our Claude Code plugins in Docker Sandboxes

How to run Claude Code inside a
[Docker Sandbox](https://docs.docker.com/ai/sandboxes/) (`sbx`), in any project
of your own, with the team's plugins from
[cap_skills](https://github.com/Cellular-Semantics/cap_skills) pinned for that
project with [cs-plugin](https://github.com/ubyndr/cs-plugin).

You do not need to clone this repository to use the plugins: follow
[GUIDE.md](GUIDE.md) in your own project. This repository is the guide plus a
worked example: its own plugin pins, the files cs-plugin generated from them,
and recorded example runs.

## Quick start

Once uv, the `cs-plugin` shortcut, sbx and the network policy are set up
([GUIDE.md](GUIDE.md) steps 1–4), in your own project:

```sh
cd ~/github/my-project                       # any project of yours
cs-plugin add cap-tools                      # writes plugins.toml and .claude/; commit them
sbx create --name my-project claude .
sbx exec -e PROJ="$PWD" my-project bash -lc 'cd "$PROJ" && uv tool run --from "git+https://github.com/ubyndr/cs-plugin@pkg-cs-plugin--v0.1.1#subdirectory=packages/cs-plugin" cs-plugin sync'
sbx run --name my-project                    # type /login once, then try a prompt from examples/
```

In a project that already has a `plugins.toml` (such as this one, or a
co-worker's), skip `cs-plugin add`.

Or run one prompt without opening a session, with
[scripts/sbx-claude.sh](scripts/sbx-claude.sh) (copy it into your project
first):

```sh
./scripts/sbx-claude.sh my-project "/cap-tools:cap-datasets list Human Cell Atlas datasets about the lung"
```

Or call the `cap` CLI the skills use, without Claude (see
[examples/03-cap-cli.md](examples/03-cap-cli.md)):

```sh
sbx exec my-project bash -lc 'uv tool run --from "git+https://github.com/Cellular-Semantics/cap_skills@v0.4.0#subdirectory=packages/cap-client" cap datasets --consortium "Human Cell Atlas" --name lung --format text'
```
